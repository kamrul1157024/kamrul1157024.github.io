Slide 1

Local rule №1: multiply

Zoom into one gate: s = w·x. A gradient g arrives at s from the right ("L changes this much when s changes"). The gate hands it backward to both inputs — but each one scaled by the other input. Step through it.

MULTIPLY RULE
w's gradient is the upstream gradient scaled by the other input — nudge w by ε and s moves by x·ε.
Slide 2

Local rule №2: addition is distribution

The gate y = s + b does nothing to the gradient at all — it photocopies it. One gradient g arrives at y; two identical copies leave, one down each input branch. Watch it split.

ADD RULE — GRADIENT DISTRIBUTES
and the mirror image: when one value feeds N different places, its total gradient is the sum of all N copies coming back. Distribution forward, summation backward. (Slide 7 uses this.)
Slide 3

Two more rules: subtract and square

The last two gates of the graph. Subtract (e = y − t) is add's sibling: the gradient copies to the first input and copies negated to the second. Square (L = e²) scales the incoming gradient by 2e — the only other gate that changes it. Step through square first (it feeds the subtract gate), then subtract.

L = e²
e = y − t
SUBTRACT & SQUARE
four gates, four rules: multiply scales by the other input, add copies, subtract copies with a sign, square scales by 2·input. That is the entire vocabulary of backprop.
Slide 4

The chain: every gate does its one rule

All four rules, one graph: y = w·x + b, loss L = (y − t)². Move the sliders and step it forward — then step it backward: the square gate scales the gradient, the subtract gate signs it, the add gate copies it, the multiply gate scales it again. What arrives at w is the chain rule — one multiplication per gate on the path.

CHAIN RULE — the gradient at w is the product of the local rules along the path:
nothing else exists. Every backprop in every framework is these local rules, composed.

Slide 6

The formula morphs again: vectors → matrices

Now B=8 samples and M=3 outputs at once: Y = X·W + b. The gradient formula must morph too — press Morph ▸. The interesting moment: the product only fits together one way, and that's where the transpose comes from. It's not a new rule — it's the multiply rule with shapes that line up.

THE MATRIX RULES
gradient w.r.t. a factor = upstream gradient × the OTHER factor, transposed so inner dimensions cancel — slide 1's multiply rule, summed over the batch.
Slide 7

Distribution in reverse — and LoRA

The bias b is added to all 8 rows of Y. Slide 2 said a value used in N places collects N gradient copies that sum — so ∂L/∂b = Σ_b G. Step through the copies converging into one. Then the same chain with a constraint: LoRA freezes W and learns a rank-r update A·B instead.

WHY LORA WORKS
The price: if the needed update isn't low-rank, LoRA plateaus where full fine-tuning would keep going. The payoff: a fraction of the parameters, one frozen base model, many swappable adapters.
Slide 8

From samples to gradients: a batch points the right way on average

The previous slide showed that a random sample has, on average, the same shape as the whole dataset. The same holds for gradients: a sample's gradient points the same way as the full gradient, on average. That sample is a batch, and training batch by batch is stochastic gradient descent. Press Sample a batch ▸ and watch the sample mean hug the true mean — then watch the loss still go down.

WHY BATCHING WORKS
the expected gradient of a random batch equals the full-dataset gradient; the noise shrinks like 1/B. So we trade a little noise for a huge speedup — and the noise itself often helps escape sharp minima.
Slide 9

Embeddings: a lookup table of trainable vectors

A token (a word, a character) is just an integer id. The embedding table E holds one trainable vector per id — the network reads a row, uses it, and backprop updates only that row. Watch the token cat point to its row, then the update change only cat's row while every other row greys out, untouched.

EMBEDDING RULE
an embedding is a vector we maintain and update — the backward pass touches only the rows that were read this step. Sparse update: ids not in the batch get zero gradient.
Slide 10

The feed-forward network: what the matrix actually does

Every token position passes through the same little network: FFN(h) = W₂ · gelu(W₁h + b₁) + b₂ — a vector in, a vector out. The key is the matrix multiply: every output unit is a dot product with every input feature, so each output relates everything to everything. Stack many such equations with their own parameters and the network can capture a huge variety of features. Step through one row, then the whole matrix, then the backward pass.

FFN = MANY EQUATIONS, EACH MIXING EVERYTHING
one row of W is one equation; the gradient of W[j,i] is again "upstream × the other input". The second matmul (W₂) remixes the hidden features back down — same rule, twice.
Slide 11

Attention: let tokens look at each other

Each token makes a query, a key and a value. A token's output is a weighted mix of the values it can see — weights from query·key scores, softmaxed, and masked so a token can't peek at the future. Step through the scores, the mask, the softmax, and the weighted sum — then the backward pass flowing through all of it.

ATTENTION
the softmax row is the only nonlinearity: its backward is "subtract the weighted mean, then scale". Everything else is the multiply rule from slide 1 with transposes.
Slide 12

LayerNorm: keep the numbers sane

Deep stacks drift — activations blow up or vanish. LayerNorm re-centers and re-scales each token's vector to mean 0, variance 1, then applies a learned gain γ and shift β. The backward pass is a projection: it removes the parts of the gradient that would only shift or stretch the vector, then divides by σ.

LAYERNORM
the backward pass projects g onto the subspace that preserves mean and variance — that's why LayerNorm is stable to train through.
Slide 15

Residual networks: the add gate that saves deep learning

Stack many layers and gradients vanish — each multiply shrinks them. The residual connection is disarmingly simple: y = F(x) + x. It exists because of slide 2: the add gate photocopies the gradient, so a copy of g reaches every early layer unscaled, no matter how deep. Watch the gradient split at the add and one copy travel the skip path untouched.

RESIDUAL RULE — the skip is the add gate from slide 2:
the gradient is the transformed part plus an untouched copy of g — the "+g" term is why a 100-layer network still trains. Residuals don't remove the work; they guarantee a clean highway for the gradient to flow home.
PITFALLS — what residuals do not fix: • not a free lunch — F(x) can still learn to be useless (dead branches); the skip just keeps the gradient alive. • shape must match — x and F(x) need the same dimensions, or you need a projection on the skip. • scale drift — without normalization the residual stream can grow with depth (that's why LN sits inside the block). • shallow illusion — very deep residual nets behave like ensembles of shallower paths; depth ≠ depth of computation.
Slide 13

The full block: forward, predict one token, backward

Wire it together: tokens → embeddings → [LayerNorm → attention → residual → LayerNorm → FFN → residual] → LayerNorm → unembed → softmax → a probability for the next token. Press Forward ▸ to push a sentence through and predict one token; Backward ▸ to send the loss gradient back through every component we built.

THE BLOCK
the residual add is slide 2's distribution — the gradient photocopies down both branches, so deep stacks train. The whole block is the four rules, composed a few hundred times.
Slide 14

KV cache: stop recomputing the past

Generating text is a loop: feed the newest token, predict the next one, repeat. Attention for the newest token needs the keys and values of every earlier token, and those never change once computed. Without a cache the model recomputes them every step; with a KV cache it computes each one once and reads it back. Step through both lanes side by side, then see how GQA shrinks the cache itself.

new this step read from cache recomputed (same value as last step) masked future computed, then thrown away
KV CACHE & GQA
The cache trades memory for compute: each new token stays cheap, but the cache grows with every token, layer and K/V head. That is why long contexts and big batches push models toward GQA.

Slide

Sum and dot product: many inputs, one output

Two operations collapse a vector into one number. A sum is an add gate with many inputs, so by the add rule the incoming gradient is copied to every input. A dot product is n multiply gates feeding one sum, so each receives the copied gradient times its own partner . Two rules you already know, no new calculus.

SUM AND DOT PRODUCT
The gradient of a vector always has the same shape as the vector. That is a free check you can run on every formula from here on.

A random sample looks like the whole dataset

Before any model: why can we learn from a small random piece of the data? Pick examples uniformly at random (every example equally likely) and the sample is a small, noisy copy of the whole dataset. Its histogram takes the same shape and its mean lands near the true mean, and the noise shrinks predictably as the sample grows. Step through samples of 1, 10, 100 and 1000 points from a dataset of 20,000.

WHY A SAMPLE REPRESENTS THE DATA
The sample mean is right on average (unbiased), and its typical error falls like . 100× more data buys only 10× less noise, which is why training uses many small samples rather than one giant one.
Slide

More steps for the same compute: gradient descent vs SGD

Fit a line to 2,000 points. Full-batch gradient descent reads all 2,000 points to take one careful step. Mini-batch SGD reads 32 random points per step, so one pass over the data (an epoch) buys 62 noisy steps. Each noisy step points the right way on average (previous slide), and many cheap steps beat a few perfect ones.

GD VS SGD
The price is noise: SGD jitters around the minimum instead of landing on it. In practice the learning rate is lowered over time (a schedule) so the jitter dies down.
Slide

Train, validation, test: three piles, three jobs

A model that fits its training data can still be useless on new data (it may have memorized noise). So we shuffle the data once and split it three ways: the training set to fit the weights, the validation set (also called the dev set) to choose hyperparameters (anything we pick rather than learn: the polynomial degree here, λ, the learning rate, the number of layers), and the test set, locked away and used once at the very end as an honest estimate of real-world performance.

THE SPLIT
Each pile answers one question: training fits the weights, validation picks the settings, test grades the final choice. The moment the test set influences a decision, it stops being a test.

A 30-layer network, with and without normalization

Now a real network: 30 layers of 32 tanh units, trained with the same learning rate on a small regression task (learning rate 0.01, decayed to 0 over training). Without normalization, each layer's output distribution drifts: a slightly small weight scale shrinks the signal to nothing, a slightly large one pins units at ±1. Either way training stalls. Re-normalizing every layer's pre-activations keeps the distribution in the healthy zone, whatever the weight scale. The top lane shows the forward distributions, the lane under it the backward (gradient) distributions at the same layers. All the numbers below are computed live in your browser.

WHAT NORMALIZATION BUYS
Normalization pins every layer's input to mean ≈ 0, spread ≈ 1, the zone where tanh's slope is healthy, so the depth product neither dies nor explodes. Careful initialization can do the same at the start, but it is a knife-edge; normalization holds it during training too. The next two slides show the two ways to compute μ and σ.
Slide

BatchNorm: normalize each feature across the batch

Batch normalization (2015) was the first normalization layer to make very deep networks train easily. Take a batch: rows are examples, columns are features. For each feature (column), compute its mean and spread over the batch, then rescale that column to mean 0 and spread 1. Finally a learned scale γ and shift β per feature let the network undo the normalization wherever that helps.

BATCHNORM
The catch: statistics come from the other examples in the batch. Small batches give noisy statistics, a batch of one has no spread at all, and training and inference behave differently.
Slide

BatchNorm vs LayerNorm: which axis gets normalized

Same matrix, rows = examples, columns = features. BatchNorm normalizes down each column, mixing examples. LayerNorm normalizes across each row: one example's own features, nothing else. That one change makes LayerNorm independent of the batch, the same at training and inference, and fine with a batch of one. That is why every transformer uses it (or its cheaper cousin, RMSNorm).

TWO AXES
In a transformer the tensor is batch × tokens × features. LayerNorm normalizes each token's feature vector on its own, so sequence length, padding and batch size never leak into the statistics.

Why regularize: a model that memorizes

Ten training points, a degree-9 polynomial: ten knobs for ten points. With no regularization the model threads every training point — it has memorized the noise, and the held-out points (blue rings) land far from the curve. Regularization adds a price for big weights: L_total = L_data + λ·R(w). Drag λ up from 0 and watch three things move together: the curve smooths, the weights shrink, and held-out error falls — until λ is so big the model underfits.

the 10 weights w₀ … w₉ (darker = bigger |w|)
THE IDEA
inside the model, overfitting looks like huge, finely balanced weights that cancel each other to hit every noisy point. Charging for weight size trades a little training error for a much simpler function. λ is the dial: 0 = memorize, moderate = generalize, huge = underfit. The next slides show exactly what this extra term does to backprop.
Slide

Regularization in backprop: one more branch, summed at the weight

Adding λ·R(w) to the loss adds a second path from the weight to the loss — nothing inside the network changes. Going backward, the + gate photocopies the gradient down both branches (the add rule). And because w feeds two places, the two gradients that come back are summed at w — the add rule's mirror image. Step through it, then switch to L1: only the bottom branch's local rule changes.

WHAT REGULARIZATION DOES TO THE GRADIENT
the penalty's gradient never travels through the network — it depends on w alone. That's why frameworks usually leave it out of the loss and add λw straight into each weight's update ("weight decay"). Backprop through the layers is exactly what it was before.
Slide

L2 = weight decay: the pull is proportional to the weight

L2's extra gradient is λw — twice the weight, twice the pull. Put it in the update and it factors: w ← (1 − ηλ)·w − η·g_data. Every step first multiplies every weight by the same factor (1 − ηλ), then takes the data step — hence the name weight decay. To see the penalty on its own, these five weights get no data gradient at all.

η = 0.1
L2 IN THE UPDATE
with real data, a weight settles where the data's pull balances λw — it survives only while the data keeps paying for it. Big weights are taxed hardest, so no single weight can grow huge: that's the smooth curve you got on the first regularization slide.
Slide

L1: a constant pull that drives weights to exactly zero

L1's extra gradient is λ·sign(w) — the same ±λ whether the weight is 2.0 or 0.01. So every step moves every weight the same amount toward zero. Small weights get there first and are switched off — exactly 0. (Plain gradient steps would jitter ±ηλ around zero; real L1 optimizers clip at zero with a "soft-threshold" step, which is what's shown.) The dashed lines are the same weights under L2, for comparison.

η = 0.1
L1 IN THE UPDATE
L2's pull fades as a weight shrinks (λw → 0), so weights get small but linger. L1's pull never fades, so any weight the data doesn't defend goes all the way to 0 — L1 makes models sparse.
Slide

L1 vs L2: why only L1 gives exact zeros — the picture

Two weights, w₁ and w₂. The ellipses are the data loss; its best point ★ wants both weights nonzero. A penalty is equivalent to a budget: stay inside a circle for L2 (w₁² + w₂² ≤ t²) or a diamond for L1 (|w₁| + |w₂| ≤ t). The answer ● is where the smallest ellipse first touches the shape. A circle has no corners, so it's touched somewhere smooth and both weights survive. A diamond's corners sit on the axes and poke out toward the ellipses, so the touch usually lands on a corner — where one weight is exactly 0. Drag the budget.

A PENALTY IS A BUDGET
the same story as the gradient view: sitting on an axis, the L1 pull is still ±λ — strong enough to hold a weight at 0 unless the data pushes harder than λ. L2's pull λw is zero at 0, so it can never hold a weight there.
Slide

Dropout: regularize with noise — and what it does to backprop

Dropout fights overfitting differently. During training, every step switches off a random set of units — each kept with probability q. No unit can count on a particular partner being there, so each feature has to be useful on its own. In backprop a dropped unit is a dead end: its output was multiplied by 0, so by the multiply rule its gradient is multiplied by 0 too, and the weights feeding it learn nothing from this example.

DROPOUT, FORWARD AND BACKWARD
dividing by q ("inverted dropout") keeps E[h̃] = h, so the next layer sees the same average signal in training and at test time. At test time there's no mask and no scaling — the full network behaves like an average of all the thinned networks it trained. Note: PyTorch's nn.Dropout(p) takes the drop probability, p = 1 − q.

In practice: what's used most — and the optimizer catch

Every regularizer here changes backprop in one of two ways: it adds a term to each weight's gradient (L2, L1), or it masks the backward path (dropout). Here's how they're used today.

THE OPTIMIZER CATCH: L2 IN THE LOSS ≠ WEIGHT DECAY WITH ADAM
Adam divides each weight's step by that weight's own gradient scale √v̂. Put λw inside the gradient and the decay gets divided too: weights with big gradients barely decay, weights with tiny gradients decay a lot. PITFALLS
• don't decay biases or LayerNorm γ/β — the usual practice is to exclude them; shrinking them costs accuracy and buys no generalization.
• turn dropout off at eval (model.eval()) — leave it on and predictions change from run to run.
• too much λ underfits — the right edge of the first regularization slide. Tune λ on held-out data, never on the test set.
• regularization isn't more data — it's a preference for simpler functions. When you can get more (or augmented) data, that usually helps more.
Backpropagation is four local rules — multiply, add, subtract, square — chained over a computation graph. Addition distributes the gradient; multiplication scales it by the other input; matrices only add shape bookkeeping. LoRA is the same chain with a rank constraint on where it may act.
